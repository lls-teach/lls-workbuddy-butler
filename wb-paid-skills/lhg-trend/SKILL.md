# 近 30 天热点扫描（lhg-trend）

训练数据和通用搜索引擎对"正在发生的事"天然滞后。本 skill 用多源并行搜索 + 真实互动热度排序 + 健康检查诚实降级，回答"这个话题近 30 天到底火不火、为什么火、还能不能追"。

**方法借鉴**：`mvanhorn/last30days-skill`（MIT License）。本 skill 为独立重写（中文优先、平台中立、增加中文信源与选题模式），非原项目翻译或分支。

## 模式选择（先定模式再开工）

| 模式 | 输入 | 输出 |
|---|---|---|
| 主题模式 | 一个明确主题（如"固态电池量产""AI 编程 agent 涨价"） | 该主题近 30 天讨论全景：结论 → 事实 → 引用 → 观点对照 → 动量判断 → 跟进查询 |
| 发现模式（选题模式） | 一个领域/赛道（如"AI 自媒体""新能源"） | 5–10 个候选话题，按跨平台热度排序，每个附"三件套"；末尾可直接投喂 lhg-benchmark-topic-factory |

## Phase 1：查询规划（先拆词，再并行）

1. 把主题拆成 **3–6 组检索词**：核心词组、同义/行话组、人物/公司组、争议词组（如"骗局/崩盘/封杀"类对立词，避免只搜到一面）。
2. 每组检索词派一路并行搜索（只读子 agent 或并行联网搜索均可），**不要串行等**。
3. 排序原则：**搜"人"不搜"编辑"**——不看媒体通稿看真实互动。用点赞数、播放量、评论数、转发数、Polymarket 预测赔率等做跨平台热度排序；编辑精选内容只做背景参考，不计入热度分。

## Phase 2：信源分层（按可达性分三层，缺失就降级）

**A 层：免费免 key（优先跑通）**
- Reddit（相关 subreddit 热帖 + 评论数）、Hacker News（热榜 + 评论质量）
- Polymarket（相关事件预测赔率 = 真金白银的热度投票）
- GitHub（相关仓库 star 增速、issue 讨论热度）、arXiv（近 30 天相关论文数）
- Techmeme（科技媒体头条聚合，判断"是否已出圈"）

**B 层：需 key / 登录（有条件再跑）**
- X（推文互动量）、YouTube（视频播放量/评论区）、TikTok / Instagram（短视频播放与话题标签量）

**C 层：中文信源（权重上调——本 skill 中文优先）**
- 抖音：热搜榜、话题播放量、高赞评论区（判断大众情绪）
- 微博：热搜榜、话题阅读量/讨论量
- B 站：相关视频播放与弹幕密度；知乎：热榜与高赞回答

**时间窗口**：统一卡 **30 天硬窗口**（从今天往前推 30 天，报告中写明起止日期）。窗口外的内容只做"背景"，不计热度分，不混入结论。

## Phase 3：纪律（红线，违反即自检 FAIL）

1. **健康检查先行**：每个信源先做可达性检查。挂了的在报告中写明"XX 信源本次不可用，未采用"，**不硬凑数、不拿旧数据冒充**。
2. **引用必注出处**：每个热度数字后面跟可查的出处（链接或"平台+榜单+日期"）。写不出来源的数字不许写。
3. **缺数据直说**：某平台搜不到相关内容，写"未找到"，不编造"反响平平"之类的结论。

## Phase 4：输出结构（固定模板）

```
# {主题}·近 30 天热点扫描（{起始日期} ~ {结束日期}）

## 一句话结论
{火/不火/正在升温/已经过气，一句话 + 最关键的一个数字证据}

## 关键事实（每个附跨平台数字证据）
- {事实}（Reddit r/xxx 热帖 2.3k 赞，链接；微博话题阅读量 X 亿，链接）

## 代表性引用（注明出处与热度）
- "{原话摘录}" —— 出处（平台/账号/时间），热度（点赞/播放）

## 多方观点对照
| 立场 | 代表声音 | 出处 |
|---|---|---|
| 看多 | ... | ... |
| 看空 | ... | ... |
| 吃瓜 | ... | ... |

## 动量判断
{升温中 / 见顶 / 衰退 + 依据：热度曲线是爬坡还是断崖，有无第二波催化剂}

## 可直接运行的跟进查询
- {下一组检索词}（建议信源：...）

## 信源健康检查
| 信源 | 状态 | 说明 |
|---|---|---|
| Reddit | ✅ 正常 | ... |
| X | ❌ 不可用 | 本次未登录，未采用 |

## （发现模式追加）候选话题榜（按热度排序，5–10 个）
### 1. {话题名}（热度分：高/中）
- 为什么值得做：{数据证据，如"抖音话题播放 8 亿 + 微博热搜第 3 + HN 前 10"}
- 建议切入角度：{1–2 个具体角度}
- 对标账号是否已做：{已做/未做/部分做了 + 是谁}
...
---
> 以上候选话题可直接投喂 lhg-benchmark-topic-factory 做对标深拆与选题库生产（联动说明）。
```

**热点三件套**（每个热点/候选话题必须有，缺一项即自检 FAIL）：
1. 为什么值得做（数据证据，不是感觉）
2. 建议切入角度（具体到"从哪个口子讲"）
3. 对标账号是否已做（已做/未做 + 是谁，避免撞车或方便差异化）

## 自检与反馈（Self-QC）

本 skill 在每次执行后做一次轻量自检；只有发现疑似自身缺陷时，才跑完整冒烟测试并打扰用户。自迭代协议 v1.0：

1. 自检门（每次输出后自动执行，不额外输出）：
   - 是否写明了 30 天起止日期？有无把窗口外内容计入热度？
   - 每个热度数字是否附了可查出处？有无"未找到"被写成肯定结论？
   - 信源健康检查是否如实？失效信源是否标注"未采用"，而非编了数字？
   - 每个热点是否有完整的"三件套"？发现模式候选是否为 5–10 个且按热度排序？
   - 是否出现平台专有工具名（违反平台中立）？
2. 若命中任一项 → 运行 `references/smoke-test.md` 的标准用例，记录通过/失败项。
3. 输出「质检报告」：问题描述 + 冒烟测试结果 + 修改方案（具体到本 SKILL.md 的哪一节、建议怎么改）。
4. 问题反馈：质检报告给用户过目后，由用户通过 WorkBuddy 资产页联系作者反馈问题，作者跟进修复。
5. 修复后必须重跑冒烟测试全绿，再随更新版本交付。
6. 自检通过时不输出质检报告、不打扰用户。
