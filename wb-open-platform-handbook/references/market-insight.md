# 市场洞察：技能为什么会爆量（2026-10 全量普查结论）

> 来源：非官方，社区实测 ｜ 数据日期：2026-10-26 深夜全量普查（31,740 个技能，覆盖率 99.4%）
> 原始数据：本仓库 `skill-market-research/`（报告 + skills_full.csv 全量含 skill_id）
> 用途：为创作者回答"为什么他的 skill 火了我的没人用""怎么上架才有流量"。规则如有出入，以平台实际机制为准。

## 一句话结论

**爆量 ≠ 搬运。爆量 = 被外部验证过的成熟需求 × 本地市场空白 × 最早入场 × 中文搜索词命名 × 排序马太效应。** 搬运只是拿到"成熟产品"的最廉价手段，不是爆的原因——同样搬运的技能有几万个，其中 60% 使用量不到 10 次。

## 五个机制（缺一不可）

### 1. 成熟产品 × 真空市场

榜单前几名（PDF 文档处理 111 万次 / Excel 表格处理 59 万次 / PPT 演示文稿 36 万次，内部 name 为 `pdf`/`xlsx`/`pptx`）疑似移植自 Anthropic 开源技能（旧版快照 + 平台化改造，frontmatter 仍保留 `license: Proprietary` 字样）。它们的共同点：**全球 Claude 生态验证过的成熟品**，落进 2026 年 9 月前的 WorkBuddy 真空市场——当时全市场每月新增技能不足百个，刚需品类几乎无人做。零研发成本拿到十倍质量的成熟产品，是搬运者的全部优势。

### 2. 时机：流量洪峰的前夜

xlsx/pptx 于 2026-09-06 上架，正踩在平台爆发前夜：9 月新增 12,988 个技能、10 月新增 17,757 个（供给侧与用户量同步暴涨）。早两周上架 = 独吃整个增量市场的第一波搜索与推荐流量。10 月之后再做同样的事，同样的动作只剩 60% 技能 <10 次使用的下场。**时机是搬运者真正稀缺的东西，不是搬运本身。**

### 3. 排序马太效应

市场列表默认按"使用量"排序。头部一旦形成：曝光 → 安装 → 使用 → 排名更靠前 → 更多曝光。实测数据：前 22 名（0.07%）吃掉 53% 使用量，前 100 名（0.3%）吃掉 73%（CR100=73%）。这个循环一旦转起来，后来者无法打破。

### 4. 命名即 SEO + Agent 自动调用产生"被动使用量"

- `display_name_zh` 用全民级中文搜索词直给（"PDF 文档处理"），市场搜索与推荐都吃这个字段；
- 更关键：技能是 **Agent 自动调用**的——用户只要装了，之后每次让 WorkBuddy 处理 PDF，技能被自动加载执行。工具型技能一次任务还能触发多次调用。111 万"使用量"对应的真实用户数远小于表面数字，但排序机制只认这个数字。

### 5. 幸存者偏差警示（给你的反例）

全市场 31,740 个技能中：使用量 <100 次的有 27,946 个（88%），<10 次的有 18,977 个（60%）。搬运/开源移植的技能成千上万（source=github/clawhub 共 54 个头部之外，"others"来源 31,556 个），爆的永远只有最早卡位的极少数。**"上架即自然流量"不存在。**

## 给创作者的行动规则（管家在"上架策略/冷启动"咨询时直接引用）

1. **选品**：优先已被外部验证的需求（GitHub 高星 skill、开源工具对应能力），不要赌需求真伪；对照本仓库 `skill-market-research/skills_full.csv` 查赛道密度。
2. **命名**：`display_name_zh` 必须含高频搜索词、中文场景直给（参考"公众号排版引擎"，不要"wechat-typesetter"）；description_zh 前两句写场景词。
3. **选位**：避开红海分类（效率工具 15,334 个 / 办公协同 7,681 个），优先供给稀疏分类（网站部署 299 个 / 投资理财 1,253 个 / 双十一 17 个）；一个技能可挂多个分类，用满。
4. **时机**：新品类出现（平台新功能、新分类、热点事件）后**尽快上架占位**；成熟品类新入场者靠差异化命名+站外引流，不与头部正面拼排序。
5. **冷启动**：安装后必须"用一次"才算有效——把安装用户转化为实际使用（课堂话术："装完立刻让 AI 用它干一件活"）才能推动排序；榜单只认 use_count。
6. **辨别搬运（教学素材）**：内部 name 是裸英文通用词（pdf/xlsx/pptx/humanizer）、描述与 GitHub 开源仓库逐字一致、无自定义图标（icon 为 `letter:auto` 或平台通用封面）、上架日期扎堆——四条占两条即高度可疑。引用他人成果时核对 license（Anthropic 官方技能为 Proprietary，搬运有下架风险）。

## 命名 SEO 实测细则（2026-10-27 对 31,740 条二次挖掘）

全体使用量中位数仅 6，TOP100 中位数 34,851。名称层面的实测规律：

1. **头部名 = 全民搜索词（品类/格式/平台词）+ 动作词**：「PDF 文档处理」「Excel 表格处理」「Word 文档生成」「去AI味」（痛点词本身成名）。名字平均 9.8 字，不比全体长——赢在词准，不在名长。
2. **含高频场景词的名中位表现最好**：名含「写作」中位使用量 24、「图片」24、「视频」18、「搜索」17（全体中位 6）。这些是用户真会打进搜索框的词。
3. **弱词警告**：「助手」被 2,342 个技能在用（中位 10）、「管家」105 个（中位 9）、「神器/大师/一键」均为稀释词——不提供搜索增量。2026-10-27 起 lls 家族复合型技能弃用「管家」，改用全面型词（如「格式转换大全」）。
4. **全面型词的真实数据**：「大全」全场仅 9 个（中位 22，样本太小不构成优势证据）；「全能」50 个中位 62、3 个进 TOP500；「套件」的头部案例（企业微信/钉钉/飞书套件）是品牌势能不是词的功劳。堆词长名反例：「视频短视频图片音乐音频配音口播数字人全能创作」仅 5,706 次。**结论：全面型词可作定位修饰，但不能替代搜索词；真正的 SEO 杠杆在描述前两句堆满场景搜索词。**
5. **命名公式（lls 家族定版）**：单点技能 = 搜索词 + 动作/品类词（+可选定位修饰）；复合技能 = 核心搜索词 + 全面型词（大全/全能）；描述前两句必须出现 3 个以上场景搜索词。
