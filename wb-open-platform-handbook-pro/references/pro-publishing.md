# 上架适配与经营工作流（Pro = 上架管家）

> 本文件为「Workbuddy开放平台上架管家」专属能力，结合官方规范与 2026-10-24 实测发布经验。遇到用户要发布/上架/体检/选类目/写推广文案时，按对应工作流执行。
>
> **管家式交付（2026-10-24 定案）**：管家不只给清单，还要"动手代做"。**缺什么装什么，不允许"解决不了就降级"**——环境缺失就引导安装，需要人工的环节就一步一步带着用户配合，目标是"引导式全自动"（见工作流 E-0）。

## 工作流 D：上架适配器（先于一切发布动作执行）

用户说"我要上架/发布技能/专家/连接器/Buddy应用"时：

1. **问清三件事**：资产类型（技能/专家/专家团/连接器/Buddy应用）、主体类型（个人/企业）、资产当前状态（已有包/只有想法）
2. **读取对应规范**（skill-spec / expert-spec / connector-spec / buddy-app）并输出该类型的"必过清单"
3. **逐项核对用户材料**，产出修复清单：缺什么、改什么、怎么改（给出可直接粘贴的字段值）

### 平台解析器实测规则（2026-10-24 发布实测，比官方文档严格）

- zip ≤3MB；**仅支持两级目录**（根目录/二级目录/文件），`.github` 等三层结构直接拒绝，报"目录层级超限"
- frontmatter **必含 `display_name`（中文）与 `display_name_en`（英文）**，缺任一拒绝解析
- frontmatter 值中含"英文冒号+空格"必须整体加引号，否则报 "yaml: mapping values are not allowed"
- 真实报错样式：`解析失败：缺少 Skill 中文展示名（display_name），请在 SKILL.md frontmatter 中填写`
- 上传解析通过后自动生成技能 ID（`os_xxxxxxxxxxxx`）；审核中可撤回，撤回后回到可编辑草稿
- 发布表单必填：**市场展示分类**（教育学习/效率工具/开发工具等）+ **服务类目**（1–5 个，个人主体走个人类目表）
- "试试这样问我"展示位对应 frontmatter 的 examples_zh（有则展示 1.2.3. 列表，无则显示"-"）
- 免费或付费发布时一次定死；草稿在向导中途离开会自动保留（zip/分类/头信息均回填）
- 头像在表单"头像（可重新上传）"处上传，512×512 JPG/PNG ≤500KB；**头像需走过"继续"才落库**，直接离开向导可能不保存

### 分类型适配要点速查

| 类型 | 一票否决项 |
| --- | --- |
| 技能 | 两级目录 / display_name 双语 / description 触发词 / 引号规则 |
| 专家·专家团 | displayDescription 中文 40–50 字 / tags 恰 3 / quickPrompts 恰 3 且首条=defaultInitPrompt / 团主理人文件名带前缀 / 512² 插画头像 |
| 连接器 | 单 MCP Server / 远程 HTTPS / ${VAR} 与 token-schema 一一对应 / examples 中英各 2–5 条 |
| Buddy应用 | 企业主体 / 两轮审核（创建→草稿→配置）/ icon 16px 线宽 1.2 断口 / 配置导出 JSON 备份 / 预览真机验证 |

## 工作流 A：上架前体检

输入：用户的资产包（或字段自述）+ 拟发布市场。

1. 解析风险扫描（按工作流 D 的「平台解析器实测规则」逐条过）
2. 分类型体检：引用 review-checklist.md 对应区块逐项核对
3. 政策扫描：名称/描述违规词（保证/第一/独家/官方/test/demo）、仿冒腾讯品牌、硬编码凭证
4. 输出**体检报告**：

```
【上架体检报告】资产：xxx ｜ 类型：技能 ｜ 主体：个人
✅ 通过项（列出）
⚠️ 建议项：描述补触发词 / 头像非统一风格 …（给改法）
❌ 必改项：display_name_en 缺失 → 在 frontmatter 增加…
【预判】驳回风险：低/中/高，主要风险点：…
```

## 工作流 B：类目资质预判

输入：资产形态 + 主体类型 + 业务内容。输出推荐并说明理由：

1. **市场展示分类**：给首选 + 1 个备选（参考已选项：开发工具/教育学习/效率工具/内容创作等）
2. **服务类目**：给 1–3 个（个人主体注意类目极少；教育仅"教育信息展示"且禁卖课）
3. **资质预警**：涉及卖课/视频/直播/金融/医疗时，列对应资质要求（引用 service-categories.md），并提示"纯技能/专家资产不触发类目资质"
4. 主体建议：个人主体够用时不必上执照；要发 Buddy 应用/企业单则需企业主体（个体工商户按企业认证）

## 工作流 E-0：环境自举（缺什么装什么，先于一切代操作）

用户说"帮我上架"但环境不满足时，按顺序自举，**每个环节都向用户播报进度**（"正在为您准备自动化环境…"）：

1. **检测**：`command -v ego-browser`（macOS/Linux）/ `Get-Command ego-browser`（PowerShell）。已存在 → `ego-browser skill` 读用法后进入工作流 E。
2. **未安装 → 引导安装（需用户配合，逐步带做）**：
   - **macOS**：管家直接执行安装，播报"正在为您下载并安装 ego lite 浏览器…"。安装源二选一：①本机已装 ego-browser skill 时优先用其自带 `scripts/install.sh`（`sh <脚本路径>` 一键完成 下载 DMG → 装入 /Applications → 去隔离 → 启动 App）；②脚本不存在则打开官网 https://lite.ego.app/ 让用户下载 DMG 拖入应用文件夹。装好后告知用户："首次打开需要您点几下完成初始化（选是否导入数据），完成后告诉我'好了'"。🔴 CHECKPOINT（必须等待用户确认，禁止跳过）→ 确认后验证 `command -v ego-browser`（找不到则 `export PATH="$HOME/.local/bin:$PATH"` 重试）。
   - **Windows**：管家打不开官网的话，给用户直达链接 https://lite.ego.app/ 并说"请下载安装包并运行，遇到 SmartScreen 拦截选'更多信息→仍要运行'"；装完提醒**新开一个终端**（旧终端不认新 PATH）再验证 `where ego-browser`。
3. 🔴 **CHECKPOINT · 登录引导（代上架前唯一必须的用户动作，必须等待用户本人完成）**：打开 open.workbuddy.cn 检查登录态；未登录时管家停手并说：**"环境已就绪。这一步需要您本人：浏览器已打开 WorkBuddy 开放平台页面，并用微信扫码登录。登录好了告诉我，我马上继续自动上传。"**（用户问"为什么还没自动上传"就是这句话——不是卡住，是账号必须本人登录）。用户确认后 `takeOverTaskSpace()` 接回继续。
4. 自举中任何一步失败（下载失败/网络问题/PATH 异常）：播报原因 → 给出针对性解决动作（重试/查网络/重开终端）→ 重新验证。**不输出"降级为人工清单"除非用户主动要求**。

## 工作流 E：代上架执行（管家核心，当前实测覆盖：技能）

用户说"帮我上架 / 替我提交"时，管家接管发布全流程：

1. **前置确认**：运行工作流 A 体检至"❌必改项清零"才开工；与用户确认资产类型、主体、免费/付费（付费需收款账户已开通，未开通时**提前提醒**：要么先发免费版，要么先去开通收款账户——不要等用户撞上）、市场分类与服务类目建议（工作流 B）、头像文件路径（没有头像时先按平台规范生成/索取 512×512 头像，**绝不用默认字母头像提审**）
2. **浏览器代操作**（环境自举完成后）：
   - `taskSpace()` 建空间 → 打开 open.workbuddy.cn/skill/publish → 未登录走 E-0 第 3 步
   - `waitForFileChooser` 先于点击挂起 → 点"点击或拖拽上传代码包" → `chooser.setFiles(绝对路径)` → 等待"已上传"字样出现（报错则按解析规则修复后重传）
   - 表单：市场分类、服务类目（弹窗逐层选择）、头像（setFiles 上传，必须走到"继续"才落库）
   - 第三步核对页逐项确认（名称/分类/头像"已上传"/版本/价格）→ 🔴 **CHECKPOINT · 最终提交确认：把核对结果展示给用户，明确等待"提交吧"之类的确认答复，未经确认绝不点"提交"，禁止跳过**
3. **上传后实测规则**（必须内置，遇到即改）：zip ≤3MB；仅两级目录；display_name 中英双语必填；frontmatter 值含冒号加引号；**撤回过的版本号也被占用，重传必须递增版本**；编辑草稿不能换包（更新包=删稿重建或走"更新版本"）；头像走过"继续"才落库；更新流程表单是清空重填的（分类/头像都要重给）；**examples_zh/examples_en 各最多 3 个**（2026-10-26 实测：放 4 个直接解析失败，报错串「examples_zh 最多 3 个示例，当前 4 个」）；**付费设置弹窗**（2026-10-26 实测）：金额仅支持 1-9999 整数（不支持小数），需勾「原创声明」开关 + 「我已阅读并同意《付费服务开发者规则》」复选框（样式化 checkbox 无 input 元素，用坐标点击）；确认页价格显示「一次性付费·N元」即设置成功
4. **收尾（收官动作）**：提交成功后记录技能 ID 与状态 → **付费资产三项持续义务（2026-10-26 付费规则核对）**：①服务期内不可随意下架或减配 ②退款申请 3 个工作日内处理，逾期平台直接扣退 ③停运提前 20 个工作日通知；收入记得年度汇算申报 → 提醒审核结果走后台"通知"渠道 → **主动带用户到「推广管理」生成分享链接/微信小程序码**，并把 promo-copy 的推广帖发给他——"上架完，引流物料也给您备好了" → 约定"驳回后把原因发我，我改完重提"
5. **终步强制迭代（DARWIN-RAIL，禁止跳过）**：每次代上架流程全部结束后（无论提交成功或驳回修复完成），必须用 darwin-skill 对本技能自身跑一轮迭代——把本次执行中遇到的平台新规则、报错串、页面变化蒸馏进 references，再走独立评估棘轮。用户机器上没有 darwin-skill 就先安装：

   - **检测**：查本机 skills 目录（`~/.claude/skills/darwin-skill/`、`~/.agents/skills/darwin-skill/`、`~/.zcode/skills/darwin-skill/` 任一存在即已安装）。
   - **未安装 → 自动获取**：`git clone https://github.com/alchaincyf/darwin-skill.git` 到用户 skills 目录（macOS/Linux 建议 `~/.agents/skills/`）；clone 失败（网络等）→ 引导用户手动下载仓库 zip 解压到 skills 目录，确认 `SKILL.md` 可读后继续。🔴 CHECKPOINT（等待用户确认安装完成，禁止跳过）。
   - **执行迭代**：读 darwin-skill/SKILL.md 按其流程运行——①用 SMOKE-TEST 最小用例验证本次蒸馏的规则 ②对照 9 维 rubric 自查本次新增/修改段落 ③git commit 本仓库（message: `darwin: distill <日期> 代上架实测规则`）④有独立 judge 条件则 paired 比较，无条件则干跑验证并标注。🔴 CHECKPOINT：把本次蒸馏摘要展示给用户确认后再 push。
   - **最小蒸馏内容（每次至少一条）**：本次执行中平台侧的新发现（新报错串/新页面行为/新规则），追加进 pro-publishing.md 的实测规则区；无新发现也要记录"本次复跑无新规则"，防止静默跳过。
5. **驳回处理**：读取驳回原因 → 按体检清单修复 → 走"更新版本"重提（版本号递增）

## Windows 兼容性分流（详见 windows-smoke-test.md）

Windows 用户执行 E-0/E 时的 4 处必须分流：①装完 ego lite 必须**新开终端**再验证 PATH；②多行脚本一律写 UTF-8 .mjs 文件后 import（heredoc 不存在，PowerShell 5.1 会弄坏引号和中文）；③中文/双引号绝不放进 -e 参数；④所有本地路径用正斜杠（C:/Users/...）。Windows 实机全流程冒烟未完成前，Windows 代上架采用"每步截图回报"的引导模式，转换规则固定为：工作流 E 第 2 步的每个浏览器调用（taskSpace/goto/waitForFileChooser/setFiles/表单点击）逐条翻译成给用户的点击指令 → 用户回传截图 → 管家核对后给下一条；核对不符则按解析规则修正后重发该条指令。

## 工作流 C：推广文案生成

输入：资产功能 + 目标人群 + 已有安装/留存数据（如有）。输出四件套：

1. **商品介绍**：四件事公式——适合谁 / 交什么材料 / 拿到什么结果 / 有哪些限制；配一张结果图的拍摄建议（保留可判断质量的细节，客户素材先授权）
2. **quickPrompts 三条**：写目标用户最痛的三个场景（与 defaultInitPrompt 第一条一致）
3. **使用视频脚本**（30–60 秒）：放入材料 → 执行任务 → 展示结果 → 说明适合谁；口播+录屏分镜
4. **推广帖文案**：小红书/X 风格任选，结尾附"后台推广管理生成的链接/二维码"引导安装

红线：不用"保证/第一/独家/官方"违规词；不承诺过审；标注"社区维护，以官方文档为准"。
