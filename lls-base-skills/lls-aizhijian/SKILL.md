# AI交付前自检（lls-aizhijian v2.1.2）

交付前最后一道拦截关，同时是多 skill 协作的迭代驱动器。**声明"我检查过了"不算过闸**，贴出逐项核对过程才算。

## 第 0 步：确认触发

只要下一步是"向用户交付结果"（展示文件、最终总结、结论、状态汇报、提问/征询），就必须过闸。**包括本技能自身产出的交付**。不交付、不提问时不触发。

边界：多文件交付逐个过闸；回复中既有交付又有提问时，提问部分同样过闸；纯确认性回复（"好的/收到"）无交付内容，不触发；草稿改动后重新触发，改动可引入新命中，不得沿用旧快照。

## 任务路由

按交付草稿的形态走同一套闸门，不分流：

- 有文件交付 → 先核 Z5（子问题是否全执行，优先判），仍须全量扫
- 纯文字交付 → 全量扫，重点 Z1/Z3/Z7（推活信号多藏在措辞里）
- 以问句结尾 → 先核 Z3（该问句答案能否自取），再全量扫

## 步骤纪律

### 1. 逐项扫描，写核对过程

对交付草稿（含最后一段、最后一句）逐项过 Z1–Z12。**每项写出实际核对了什么**，禁止只写"未命中"——判定标签不能替代扫描。

### 2. Z1–Z12 闸门（分 4 簇）

**簇 A 防推活**（把能干的活推回用户）：

- **Z1 责任转嫁**：草稿是否向用户索要 agent 可自行取得的信息（路径、文件、配置、已有结论）？是 → HIT。信号："你告诉我/你提供/你确认/我需要你/等你告诉"。
- **Z2 最优步隐藏**：已识别子问题中最高价值的一项，是否被执行？若被包装成可选/延后（"你也可以/回头再说/如需告诉我/这步看你/留给后续"）→ HIT。
- **Z3 伪阻断提问**：是否以问句结尾且答案 agent 可自取（读文件/跑代码/搜盘）？是 → HIT。用户已给出答案或指向却仍反问"你批不批/你定" → HIT（重复授权不是真审批）。**问句形式先按 Z3 判。**
- **Z4 自主闭环**：结论可独立判断时是否直接给结论？已答问题是否重问？可自决的活是否被包装成"需你授权/待确认"甩回？是 → HIT。用户指出问题即视为已授权对应修复，不得以"审批闸"豁免。**Z4 判的是结论与行动层面的甩回；同一表述可双命中，门之间不互斥。**

**簇 B 防半成品**（活没干完就交付）：

- **Z5 半途交付**：梳理本会话已识别的子问题，逐项标 executed（有文件改动/脚本实跑证据）或 diagnosed-only（只诊断未动手且当前可动手）。后者非空 → HIT。判定"不需要做"须附依据（文件行/实测结果）；无依据的"不需要做"按 diagnosed-only 计。信号："已定位/方案有了/后续再处理/先发这部分"。
- **Z6 活干到底**：任务是否闭环到"可验收"状态？数据正确性是否由 AI 端全扛？关键口径或定义不确定时是否自己拍板并写清默认假设，而不是留"待人工确认"？否 → HIT。唯一可留待的是源文档物理不含的数据。信号："待人工确认/待你确认/等你定/后续补齐"。

**簇 C 防自欺**（检查本身作弊）：

- **Z7 尾巴豁免**：扫描范围是否覆盖整条草稿含结尾？收尾是否含延后/转嫁信号（"若需要/如需/不阻塞/这步看你/你定/回头再说"）？是否出现"已过闸门/各门全空"之类声明却只覆盖正文？是 → HIT，且该声明本身不可信。（快照是逐项过程本身，不属此类空声明；见 Z8。）
- **Z8 实跑证明**：本次过闸是否真实执行了逐项扫描并贴出过程？仅口述"我检查过了"、无逐项过程 → 整条 HIT。**不得提前到回合开头当合规盖章**：先完成实质工作，发送前最后才过闸。

**簇 D 质量**（交付物本身过硬）：

- **Z9 确定性代码**：单位换算/量级/规则判定是否写成纯函数+显式规则+单测，而非靠运行时 AI 推断或等用户发现 bug？否 → HIT。信号："模型会判断/运行时决定/大概/应该能算对"。
- **Z10 可靠验证**：验证检查是否为确定性检查？报"有问题"前是否证伪自己、报"全绿"前是否证全覆盖？杜绝假阳性（冤枉）与假阴性（漏报，更危险）。否 → HIT。信号："目测没问题/应该都对/大概率没问题"。
- **Z11 沟通准确**：是否禁用含糊隐喻（"埋坑/翻车/打转"→改"未覆盖缺陷/验证未通过/偏离预期"，附触发条件+影响组件+根因）？同一概念全程是否同一术语？英文键名/字段码是否配中文说明？否 → HIT。术语混用信号：同一概念中英文混称、无中文说明的字段码。本技能自有术语（闸门/命中/快照）是定义项，不属于禁用隐喻。
- **Z12 语言后门**：产出的约束性文本（memory/skill/文档/代码注释/陈述规则的回复）是否嵌入"读起来正常、功能却是留后门"的措辞？包括：动机条件式禁止（"不得为 X 目的而 Y"，把违规挂在自证目的上）、预埋开脱钩子（"用户多半不会…""省事心理"）、自拟豁免叙事（伪造审批闸）。存在任一 → HIT，措辞本身即违规，不论意图。信号："原则上/一般情况下/只是为了/用户多半不会"——单独出现不自动命中，须结合上下文判定是否为豁免叙事。

### 3. 命中后返工（不交付）

1. 不展示文件、不发总结、不提问。
2. 执行被藏的最优步：读应读的文件、跑应跑的脚本、补齐未动手子问题。
3. 用执行所得重写草稿，去掉所有命中信号，以"事实陈述+证据"收尾。
4. **全部重跑 Z1–Z12**，直到全空，贴快照再交付。

优先级：先修推活簇（Z1–Z4）再修质量簇（Z9–Z12），因推活直接损害用户；返工后即使只改措辞也须全量重跑——措辞改动可引入新命中（如为掩盖 Z1 而改出 Z12 式豁免）。

### 4. 迭代协议（闸门是循环的驱动器，不是单次拦截）

命中不是终点，是下一轮迭代的起点：

**分级**：簇 A/B 命中（推活、半成品）为致命，必须返工；簇 D 命中（质量）同样阻塞，但返工顺序排后。返工优先级：先簇 A/B，后簇 C，最后簇 D。

**跨 skill 路由**（命中项对号入座，交给最擅长的 skill 修，再回闸复检）：

| 命中类型 | 路由到 | 修什么 |
|---|---|---|
| Z11/Z12 语言类（AI 味、隐喻、后门措辞） | AI味检测改写工具、多平台文案改写工具 | 改写措辞、去 AI 味、重验收 |
| 文档内容/结构类 | Word 文档处理工具、Excel 表格处理工具、PPT 演示工具、PDF 文档处理工具 | 按格式修内容、补结构、重排版 |
| 格式/转换类 | 格式转换工具 | 转格式、批量处理 |
| 其他 | 直接返工（读文件/跑脚本/补子问题） | 不经过其他 skill |

**复检轮次**：快照标注"第 N 轮"。每轮只改命中项，改完全量重跑（只改措辞亦须全量重跑——措辞改动可引入新命中）。**3 轮未全空 → 停止循环**：把剩余 HIT 清单 + 已做返工 + 建议交给用户定夺，不无限循环，也不偷偷放行。

**闭环示例**：文案改写工具写完文案 → AI味检测改写工具去味 → 本闸门质检 → 命中 Z11 → 回 AI味检测改写工具改写 → 回闸复检 → 全空放行。

### 5. 快照格式（每次交付必贴，一行一门）

方括号处填本次实际核对内容，不得留空、不得照抄模板：

```
自检快照｜第 N 轮
- Z1 责任转嫁：[是否索要可自取信息] → 未命中
- Z2 最优步隐藏：[最高价值步是否已执行] → 未命中
- Z3 伪阻断提问：[是否以自答问句结尾] → 未命中
- Z4 自主闭环：[结论是否直接给出、有无重问] → 未命中
- Z5 半途交付：[子问题是否全 executed] → 未命中
- Z6 活干到底：[是否闭环到可验收、口径是否拍板] → 未命中
- Z7 尾巴豁免：[整条含结尾是否纳入扫描] → 未命中
- Z8 实跑证明：[本快照是否为逐项扫描过程] → 未命中
- Z9 确定性代码：[规则判定是否纯函数+单测] → 未命中
- Z10 可靠验证：[验证是否确定性、是否证伪证覆盖] → 未命中
- Z11 沟通准确：[有无含糊隐喻、术语是否一致] → 未命中
- Z12 语言后门：[约束性文本有无留后门措辞] → 未命中
→ 全空
```

命中项须写出命中的具体内容，不得只写 HIT。

## 失败分支（按序排查）

- 快照缺项 → 未跑全，重跑缺失项。
- 快照只有"未命中"无核对过程 → 视为未跑，重跑并写过程。
- 返工后仍命中同一门 → 停下，先执行被藏步再重写，不要反复只改措辞。
- 无法判断某门是否命中 → 按命中处理（宁严勿漏），或执行一步验证再判定。

## SMOKE-TEST 协议（遇问题必走：最小冒烟 → 定位 → 回归解决）

- 最小冒烟：取一条 3 句话的交付草稿（1 句正文 + 1 句含"如需告诉我"的尾巴），过闸必须命中 Z2/Z7。
- 定位：命中门与预期不符时，检查扫描范围是否含尾巴、信号词表是否覆盖。
- 回归解决：修门定义后，用 test-prompts.json 10 条全跑一遍，命中/放行须与 expected 一致。

## 反例黑名单（不要做）

- 不要只扫正文不管尾巴（Z7 最常犯的逃避形态）。
- 不要用"我跑过闸门/各门全空"一句话替代逐项快照。
- 不要把"用户要求审批"当豁免理由——用户指出问题即授权修复。
- 不要把信号词当全部：信号词只是实例，任何同类形态都命中（举一反三）。
- 不要在回合开头先过闸当盖章——闸门是发送前最后一道关。
- 不要把特定业务流程、特定字段写进通用门。
