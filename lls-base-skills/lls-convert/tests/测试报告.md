# lls-convert 测试报告（2026-10-26）

## 最终结果：130 / 130 全绿

- 正例 123 条：支持矩阵内每个转换对一条真实文件转换，产物回读校验（内容标记/结构解析/格式魔数/音视频流探测）
- 负例 7 条：不支持的组合（ttf→mp4、mp3→docx、pages→docx、pdf→xlsx、svg→mp3、zip→pdf、docx→mp4）全部正确拒绝、无假产物
- 夹具 45 个真实文件，覆盖 10 大类；测试可重复执行：`python3 tests/make_fixtures.py && python3 tests/run_tests.py`

## 三轮过程（如实记录）

| 轮次 | 结果 | 说明 |
|---|---|---|
| R1 | 88/130 | 中途 VM 重启清空系统 pip 包，验证进程缓存了残缺 Pillow 桩模块，出现成批假失败；同轮发现 1 个真问题：html→docx |
| R2 | 129/130 | 环境补齐（另补 tabulate）后重跑；仅剩 md→docx 失败 |
| R3 | **130/130** | 修复后全量重跑，全绿 |

## 修复的两个真问题

1. html→docx、md→docx：LibreOffice 的 Writer Web 模式没有 docx 导出过滤器。改走「HTML/Markdown → 段落解析 → python-docx 直出」，并在 SKILL.md 标注该通道为结构化重排。
2. PDF 渲染出图：改用 PyMuPDF tobytes 按目标格式真编码，避免扩展名与实际编码不一致；Pillow 通道加产物非空断言。
