浏览器回退候选命中情况（关键结论）：
- playwright 1.64.1 期望 chromium revision 1248，本机 ms-playwright 只有 1217/1223/1234 → playwright 自带浏览器不可用。
- 脚本 findBrowserExecutable() 按候选顺序回退，命中
  C:\Program Files\Google\Chrome\Application\chrome.exe（系统 Chrome），导出正常 15 页。
  即：Windows 用户不需要额外下载 playwright 浏览器，系统 Chrome/Edge 会被自动用上。
- --browser-executable 显式指定 Edge（C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe）同样成功，15 页。

→ 本机未启用实时防护，无法实测拦截，本项记为 N/A（非通过）。

7) 超长路径（292 字符，10 层中文目录）
- node 校验：PASS
  $ node scripts/validate-waterfall-deck.mjs "...10 层.../季度 复盘.html"
  Waterfall deck validation passed: 15 cards checked.  exit=0
  （Node 会给绝对路径加 \\?\ 命名空间前缀，因此自身不受 260 限制）
- PDF 导出：FAIL，稳定复现，约 1 秒内报错
  导出失败：page.goto: net::ERR_FILE_NOT_FOUND at file:///F:/...（292 字符路径的 file URL）
  → Chrome 打不开超 260 字符的 file:// 地址，导出无法进行；需把 deck 移到短路径。
  备注：首次尝试时该命令挂起约 7 分钟无输出，杀进程后重跑即稳定复现上述报错；挂起原因未定位（不可复现）。

8) pptx 导出
$ node scripts/export-waterfall-to-pptx.mjs ... --node-modules ...
导出失败：Cannot resolve @oai/artifact-tool. Initialize the presentation workspace or pass --node-modules.
→ 私有包，npm 上不可得，pptx 导出在真机同样不可用（与此前代码级结论一致）。

结论：校验链路（node）在中文/空格/超长路径下均正常；PDF 导出在中文+空格路径下正常，且能自动回退系统 Chrome/Edge；
导出侧的两个真实限制是「依赖需自装」与「路径 >260 时 Chrome 打不开 file://」，均已补入 SKILL.md 失败分支。
